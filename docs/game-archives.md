# GUI 对局存档

普通对战和竞技场对战按本地账号保存为独立 JSON 文件。存档记录初始配置、开局随机数状态、已接受的双方决策、最新规则状态与随机数状态，以及最终结果。浏览器的公开记录与完整规则日志分开保存，进行中的对局不会通过历史记录接口公开对手的隐藏卡牌。

每次有效决策后原子替换存档。服务关闭保留未完成对局；用户从“对局存档”继续。恢复通过原始配置重放已经完成的决策，并校验代码、依赖版本、局面和随机数状态，然后接着向原存档追加记录。恢复使用新的浏览器会话标识，防止旧页面请求影响恢复后的对局。

恢复不兼容版本或损坏存档时保留原文件并显示错误。用户可以明确放弃未完成对局；竞技场放弃计一次失败。已结束或已放弃的存档可下载 JSON 日志。普通完整对局日志也可使用现有命令行回放工具验证。

竞技场存档关联轮次与对战编号。对局结果先保存，再结算竞技场战绩；重启后对照待结算编号与已推进的轮次，补做尚未完成的结算，避免重复计胜负。

默认位置为账号数据目录中的 `users/<账号 ID>/matches/<对局 UUID>.json`。`TAVERNLAB_ACCOUNT_DATA_ROOT` 可以覆盖账号数据根目录。普通对局和竞技场对局的日志都按账号隔离；竞技场运行状态另存为该账号目录下的 `arena-run.json`。账号目录的写入锁防止多个本地服务同时修改同一个账号的存档。

人类对战房间是服务器范围的共享资源，不属于任一账号的 `matches` 列表。房间记录保存在账号数据根目录下、与账号 ID 目录并列的 `rooms/<房间 UUID>.json`，其中包含两个账号席位、共享的规则日志和按席位过滤的视图。房间由服务器级房间存储恢复；普通/竞技场对局仍由各自账号的对局存档恢复。

恢复要求规则代码和卡牌数据版本通过下述兼容性检查。存档中的已接受决策可以确定性重建局面；带有时间预算的 AI 搜索在恢复后可能选择不同的后续决策。

恢复的兼容边界由 [replay_compatibility.py](../fireplace/replay_compatibility.py) 维护：记录的 replay 签名除 `source_sha256` 外必须与当前运行时逐字段严格一致；source digest 必须相同，或必须属于代码中明确列出的、经过审核的两个 predecessor-to-current 迁移对。Python、依赖版本、schema 和其他嵌套字段不会因为相近的 Git 提交或工作区状态而放宽。恢复会先重放 setup 和每个已接受动作，验证动作上下文、规范化规则状态以及精确 RNG checkpoint；只有全部检查通过，恢复后的内存日志才会迁移为当前签名。普通/竞技场账号存档会先保存迁移后的日志，再允许控制器继续；共享房间的恢复不会立即写盘，迁移后的日志随下一次有效动作保存。未知差异、损坏日志或任何动作、状态或 RNG 偏差都会拒绝恢复并保留原文件。

命令行完整日志回放只验证，不改写原文件或持久化签名迁移。它验证终局结果与规范化最终状态；包含恢复 checkpoint 时还会核对精确 RNG。早期已结束日志可以没有 checkpoint，因此不能将其最终状态验证理解为已核验完整 RNG 检查点。

曾经因读取 `powered_up` 提示而提前消耗真实对局 RNG 的旧日志，如果其 checkpoint 已经偏移，不能靠改写签名修复，仍会因精确重放失败而被拒绝。观察、UI projection 和搜索分支必须保持对真实游戏 RNG 的只读性；需要估算随机效果时应使用隔离状态或固定种子，不能改变可恢复对局的 RNG 流。

`tactical_v2` 的决策诊断保存在私有 `metadata.ai_decisions` 中，按已接受动作的 `action_seq` 关联：包括候选牌、目标、评分、随机样本、覆盖率、超时和最终选择原因。它不进入规则重放日志，也不通过状态、历史列表、详情或下载接口公开，避免泄露 AI 尚未使用的手牌。旧存档没有此字段时仍正常恢复。

诊断保留最近最多 512 条，并限制为约 4 MiB；被移除的条数记在 `metadata.ai_decisions_dropped`。单条超过 256 KiB、含非有限数值或格式不合法时，保存明确的失败原因。接受动作与诊断使用同一次存档写入；终局重复保存不会重复追加诊断。
